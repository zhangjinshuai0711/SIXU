# v0.2.1 小规模对照

这是版本收尾后的评估材料，不增加服务端能力，不调用模型 API。
六道题与三种条件构成 18 次首次回答试验。已收集的记录分为本地 v0.2.1 与
云端 v0.3.1 两批；逐项结果和条件冲突见 [实验结果](../../docs/PILOT-18-RESULTS.md)。

## 分组

| 组 | 条件 | 工具权限 |
| --- | --- | --- |
| A | 当前 Instant 直接回答 | 无工具 |
| B | 同一 Instant，增加候选、约束和反例检查提示 | 无工具 |
| C | 同一 Instant，思序自适应流程（版本按批次记录） | 仅 begin_reasoning、advance_reasoning、reasoning_status |

全部组使用同一题面的完整文字，使用全新聊天，固定模型、账号与宿主设置。
模型身份由使用者在界面确认，服务器不能独立认证。关闭其他工具及与题目有关的
记忆引用；如果宿主无法控制，记录该限制。各组都不使用执行程序、搜索、其他模型
或客观反馈。C 组使用默认 8 步预算与 `feedback=none`，不强制分支、挑战或修订。

六个题目分配六种 A/B/C 次序，抵消一部分顺序影响。该试验没有匹配总生成量，
因此不能分离“增加生成量”和“调度策略”的各自收益。六题一次试验只是初筛，
不能用于显著性或普遍能力结论。不要依据初筛分数反复改提示词并当作未见题成绩。

## 题目

| ID | 类型 | 判分依据 |
| --- | --- | --- |
| py-a | Python 默认参数、闭包、共享字典及拷贝 | 执行仓库固定程序得到 JSON |
| py-b | Python 别名、迭代器及延迟读取 | 执行仓库固定程序得到 JSON |
| sched-a | 六任务、双工人、维护窗口 | 检查可行性并穷举最优 makespan |
| sched-b | 六任务、三工人、前置约束 | 同上 |
| select-a | 预算、依赖、互斥及二级目标 | 枚举全部 256 个子集 |
| assign-a | 六人排班、禁配、顺序及不相邻约束 | 枚举全部 720 个分配 |

题面由本项目编制，不是标准公开 benchmark；难度和代表性未经校准。
不要把之前两道已知题或会议题作为这轮的未见测试。

## 准备与执行

在项目目录运行：

```bash
node --test benchmarks/pilot-v02/pilot.test.mjs
node benchmarks/pilot-v02/pilot.mjs selfcheck
node benchmarks/pilot-v02/pilot.mjs prepare
```

`selfcheck` 只检查判分工具，不调用模型，也不打印标准答案。
需要 Python 3，使用标准库且仅执行仓库内固定程序；模型回复不会作为代码执行。
`prepare` 在 Git 忽略的 `.runtime/pilot-v02/` 写入：

- `manifest.json`：固定顺序、题面 SHA-256、分组及全部待执行项。
- `prompts/`：18 份可直接发送的完整提示词。
- `responses/`：用于保留第一次完整回复原文。
- `answers/`：用于保存从原文提取的最终 JSON。

准备动作不会调用模型，不会伪造回复或成绩，重复执行不会覆盖已有实验材料。

按文件名前的顺序逐个测试。每份提示词用全新 Instant 聊天，
C 组选择思序插件，A/B 组不选择插件。不带入其他组答案、判分结果或标准答案；
测试聊天不得读取本目录的判分实现或在本地执行代码。
遇到工具失败、宿主限制或提前结束，保留第一次结果，不私下补跑选优。
同一道题的三组回复全部收集后才判分；不要用反馈继续修正首次回答。

最终 JSON 可以从回复中提取，但不得改数值、补字段或挑选最有利版本。
若模型在同一次回复中明确更正，以明确标为最终的版本评分，
同时保留原答与更正记录。无法确定最终版本则记录为歧义，不替模型选择。
示例命令仅示范参数格式，不包含标准答案：

```bash
node benchmarks/pilot-v02/pilot.mjs grade py-a .runtime/pilot-v02/answers/01-A-py-a.json
```

## 记录与解释

每次保留完整原答、最终 JSON、宿主中选择的模型、组别、时间和 C 组 run_id。
真实端到端耗时要从提交提示词到最终回答统一计时；缺失就留空。
服务端工具窗口不能冒充端到端耗时，回复字数也不能冒充 reasoning tokens。

离线判分输出：

- `passed`：Python 最终 JSON 正确，或优化题答案可行且达到全局最优。
- `constraints_passed`：优化题约束与声明数值检查；Python 不适用，返回 null。
- `explanation_review`：保留为待人工审查，程序不判断自然语言证明是否完整。

C 组额外查看真实动作、候选数量及修订次数。只有首个候选能客观判为错误、
最后结果客观正确且日志有对应变更时，才能记作一次已确认纠错；
不能依据模型自称“已经修正”或 `completed` 认定纠错成功。
首个候选无法无歧义提取为可评分答案时，将纠错能力记为无法判断。

首答结果应按实际版本和工具执行情况分别解释；不能把修复重试替换首次回答，
也不能把完成协议当作正确性的独立证明。
