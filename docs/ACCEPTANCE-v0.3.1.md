# v0.3.1 当前聊天默认启用验收

历史版本验收表。v0.4 已取消默认持续启用，当前使用方式见 `USAGE.md`，
本表不得作为 v0.4 的验收条件。

本表交由用户在真实 ChatGPT 聊天中验证，不是已经通过的结果，也不是 C 组重试。
先确认插件工具已更新为 v0.3.1；需要时刷新连接或在新聊天选择原私有云端插件。
首次任务只 @ 插件，不额外粘贴启用约定，以测试本次改动的实际效果。

在同一个新聊天依次发送：

| 步骤 | 消息 | 预期观察 |
| --- | --- | --- |
| 1 | @思序 计算 (12+7)*2，并检查结果。 | 实际调用 begin/advance，默认自适应，完成后给出 38 与 run_id |
| 2 | 将上题的乘数改成 3，重新计算。 | 不再 @；实际创建新 run，题面包含相关条件，得到 57，旧任务结果保留 |
| 3 | 这次直接回答：8+9 等于多少？ | 回答 17；本轮不调用思序，不编造 run_id |
| 4 | 计算 6*7，并检查结果。 | 不再 @；恢复调用思序，得到 42 和新的 run_id |
| 5 | 关闭思序。 | 确认关闭，不创建任务 |
| 6 | 计算 4*9。 | 回答 36，不调用思序 |
| 7 | @思序 计算 5*8，并检查结果。 | 重新启用并实际调用，得到 40 和新 run_id |

另开一个未选择插件的新聊天，普通发送一道计算题：不应声称继承了其他聊天的开启状态。
可另测只 @ 不带任务，以及询问插件用法：不应创建空任务或把使用说明当作推理题。

每步检查实际工具调用，不能仅看模型文字说“已使用”。记录实际 run_id、是否完成、
错误信息，以及是否需要额外催促；若失败，保留原回复，不反复补提示后宣称首次通过。
`completed` 仅表示流程完成，以上小题不能证明复杂问题上的效果改善。

这些行为依赖宿主模型遵循服务器指引和工具描述，服务端没有强制监听聊天的能力。
若刷新后仍未持续调用，应记录宿主与工具可见性，再判断是指引未载入还是模型未遵循。
