# 思序 v0.4.0 发布与验收

日期：2026-11-09。源码版本：`0.4.0`，状态格式：v4。

## 本次交付

- 每轮明确调用，默认中度、可指定深度；不改变当前聊天模型及其推理档位。
- 候选按版本保存；修订使旧审查/检查失效，最终答案从当前选中版本复制。
- 深度比较将审查对象与 `compared_candidate_ids` 合并计数。
  审查 C1 v2 并与 C2 v1 比较时只需提交 `["C2"]`；
  仅比较自身或引用过期候选版本不能通过。
- 对模型声明的算术、结构、选择与排程条件执行有限程序检查。
  算术工具参数公开结构化 `left/right` 运算树和 `result` 路径，
  不执行表达式字符串，也不拿模型预算答案充当期望常量。
- 创建阶段参数或来源引用不合法时返回 `INVALID_ARGUMENTS`，
  提醒本次未创建任务；未知存储错误仍使用通用错误，不泄漏数据库细节。
- 普通推进采用精简响应，`reasoning_status(detail=full)` 可恢复完整历史。
  原线性流程保留；旧自适应状态只读。

## 网页端验收

1. 深度受控纠错：C1 v1 故意写为 497，C2 v1 为 507，登记 Issue #1；
   服务返回 `REVISE`，C1 改为 v2=507，再以
   `review.candidate_id=C1`、`candidate_version=2`、
   `compared_candidate_ids=["C2"]` 比较复审并结束。
   最终 `status=completed`、`stop_reason=ready`、未解决事项为空；
   `verification_status=model_review_only`，`checks_executed=0`。
   这验收了修订后双候选门槛，不是独立算术验证。
2. 内部算术检查：原题 `137×24+89=3377`，程序对原始运算树与
   `result.total` 进行比较，候选版本审查后完成。
   最终 `final.answer=137×24+89=3377`、`final.result={"total":3377}`；
   `checks_declared=1`、`checks_executed=1`、
   `verification=service_executed`、`passed=true`、
   `verification_status=declared_checks_passed`。
   期间一次最终答案文本与候选不一致的提交被拒绝，改为候选原文后通过；
   服务未静默改写权威答案。

这些记录来自用户转述的真实工具结果，而非本仓库 CI 对线上服务的直接查询。
`completed` 只表示流程完成；程序检查也仅覆盖已经声明的结构化条件，
无法证明模型没有漏提原题条件或任意自然语言结论正确。

## 桌面端验收

用户随后在桌面端 Chat 模式仅调用一次 `reasoning_status`，
查询网页端的同一算术任务：
返回 `completed`、相同的 `final.answer/result`、
`final.verification_status=declared_checks_passed`、
`checks_declared=1`、`checks_executed=1`、
`verification=service_executed`、`passed=true`、`errors=[]`。
本次没有新建、推进或修改任务；验证的是已连接插件在两个宿主中的
同一已授权任务读取，并非桌面端单独跑完深度纠错流程。

## 本地验证与限制

```bash
npm ci
npm test
npm run check:pilot
npm run check:performance
npm run build:cloud
npm run check:bundle
```

本地回归覆盖修订后比较的并集计数、旧版本拒绝、结构化算术参数、
创建定义错误、Worker 请求/持久化纠错与打包产物检查，不调用模型 API。
精简响应的字节差异属于固定合成负载，不等于 ChatGPT 实际延迟改善。
没有新增未见题的大规模对照，不宣称普遍正确率提升或新模型能力。

早期部署时出现过旧连接器工具定义拒绝新版 `review/finalize`，
以及修订后比较仍被阻塞；这些是此前版本的故障调查，
**不是版本 7 验收后的当前状态**。旧实例的其他客户端/账号、
新用户独立部署、VPN 切换和长期可用性仍未得到全面验证。
部署自己的实例见 [云端教程](../../cloud/README.md)。
