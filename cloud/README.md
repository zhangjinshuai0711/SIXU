# 私有云端版 v0.3.1

此目录提供固定 HTTPS 云端入口的实现，替代“临时通道 → 本机”的部署路径。
私有 Sites 已部署成功，真实聊天的非实验题已完成线性流程的五次提交，
最终状态为 `completed`；随后通过云端 `reasoning_status` 读取确认。
`.openai/hosting.json` 已保存平台返回的真实 `project_id`，后续发布复用该站点。
这确认线上状态读写与基础工作流可用；VPN 切换及 C 组重试仍待完成。

## 保留的行为

- 保留 `begin_reasoning`、`advance_reasoning`、`reasoning_status`。
- 通用任务默认 `adaptive_search`；固定题默认线性，显式 `linear` 保留。
- 保留原有预算、候选修订和证据边界。
- 两条流程均复用本地版同一份推理实现，服务仍不调用模型或付费 API。
- 本地文件存储仍由 `adaptive.mjs` 提供；云端以数据库存储每次提交后的完整状态。
- 云端验证了任务读写和流程推进，不提供新的通用语义验证器。

## 入口与存储

```text
ChatGPT / Codex
       ↓
Sites 私有访问与身份验证网关
       ↓
POST /mcp → 共用推理实现 → D1 状态存储
```

`cloud/worker.mjs` 是 Worker 的源入口；`npm run build:cloud` 将它及所需模块
打包成 `dist/server/index.js`，并复制发布所需的 hosting 声明。
打包产物不包含本地 `.runtime/`、连接凭据或既有用户实验数据。

`server/discover` 提供 MCP 2026-07-28 能力发现；同时保留传统 `initialize`、
`tools/list`、`tools/call` 和 `ping`。工具定义从原有注册函数生成，不维护第二份字段列表。
`GET /health` 检查数据库表可用性；数据库缺失时返回 503。

v0.3.1 在 `initialize` 与能力发现响应提供当前对话指引，并在工具描述中同步该约定。
首次选择/@ 后要求模型对后续任务持续调用；服务端没有聊天标识或启用开关，
不能自行监听用户消息。单轮跳过、关闭、重新启用与跨聊天隔离需要宿主行为验收，
不能把返回了指引当作已经验证自动调用。见 [验收步骤](../docs/ACCEPTANCE-v0.3.1.md)。

任务按 Sites 网关提供的 `oai-authenticated-user-id` 隔离，不能用另一个用户的
`run_id` 读取或改写状态。该请求头必须来自平台已验证的网关：
本入口不是可直接裸露到公网、依赖任意客户端自报身份的认证实现。
只按本说明发布到受验证网关保护的私有 Sites，不开放匿名原始 Worker 入口。

访问期限保持创建后两小时；过期任务不能再读取或推进。
这是访问期限，不是精确的物理删除定时器：同一用户开始新任务时清理其过期记录。
未继续使用的账号可能保留过期数据库行，当前没有后台定时删除任务。
每用户最多 64 个未过期任务，插入时原子检查；每条完整状态最多 1 MiB。

每次推进根据数据库 revision 做条件更新。同时提交旧状态时，至多一个写入成功；
冲突返回 `STATE_CONFLICT`，要求先读 `reasoning_status`。
失败不会以客户端内存中的新答案冒充数据库已保存结果。
状态查询不写数据库。任务与阶段产物不写入通用应用日志。

## 发布接续

发布使用 Sites 原生托管工具，保持 owner-private，不发布到公开网站或公共插件目录。
以下步骤记录发布与验收要求：

1. 确认 `.openai/hosting.json` 是否已有真实 `project_id`。有则读取并复用该站点，
   保留现有受众；无则仅创建一次私有 MCP 站点，立即把返回 ID 原样写入该文件。
2. 使用同一站点返回的源码凭据，通过 Sites source helper 完成源码同步和打包。
   凭据只经 stdin 传入，不写入源码、命令参数或公开日志。
3. 构建并保存精确源码版本，应用 `drizzle/0000_reasoning_runs.sql`，
   验证逻辑 D1 绑定 `DB`，部署保存后的同一版本。
4. 核对发布成功和私有受众，取回平台生成的插件连接；不要另建无关 App。
5. 在目标宿主实际运行一个非实验题到 `completed`，核对数据库中的可恢复状态，
   并记录 `run_id`。再测试本机代理切换后宿主仍能调用同一固定入口。
6. 发布和宿主检查都通过后，才执行独立的修复后 C 组重试。

没有 `project_id` 时不得编造 ID、手写虚构上线地址，或声称已有可安装云端插件。
当前实例的身份、迁移和基础工具接入已通过真实工作流检查；
自行部署到其他实例时仍需执行相同验收。部署清单中的站点 ID 属于当前实例，
创建自己的实例前应去掉该 ID，不能尝试覆盖他人的站点。
